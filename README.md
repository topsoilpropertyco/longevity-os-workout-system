# Longevity OS — Workout System

A personal training brain that decides what Seth does today — lift, sprint, Zone 2, Knees Over Toes, yoga, or rest — from his Oura data, his available minutes, his location, and his last 28 days of history. It runs as an installed PWA on his iPhone, a deterministic rules engine that owns every prescription, and a local LLM on a Mac mini that writes the words around it. It costs **$0/month** and it is built so that he never has to be the air-traffic controller of his own fitness.

---

## Definition of done (from `CLAUDE.md`)

> Seth taps the home-screen icon on a Tuesday morning, sees today's session with a why line, taps Start, logs sets with the keypad, swaps one exercise, finishes, gets a Telegram summary — and Wednesday's plan already reflects it. Zero configuration on the day. Zero dollars.

Everything in this repository exists to make that one sentence true.

## Repository map

| Path | What lives there |
| --- | --- |
| `apps/web/` | The Next.js App Router PWA. Today card, week carousel, session runtime, swap carousel, clocks, dashboard, settings. Also the API route handlers: Telegram webhook, Strava webhook, Oura sync, Gemini fallback, cron. |
| `packages/engine/` | The deterministic rules engine. `src/types.ts` is the domain vocabulary; `fixtures/` holds the fixture days; `test/` holds the unit and golden-file tests. **No I/O in this package, ever.** |
| `packages/db/` | Generated Supabase types and the query helpers both the web app and the worker share. |
| `packages/integrations/` | Typed clients for Oura, Strava, Telegram and the LLM layer, over the shared `http.ts` plumbing. Every call returns a result, never a throw. |
| `worker/` | The Mac mini worker. Pulls `llm_jobs` from Supabase, calls LM Studio at `http://localhost:1234/v1`, writes results back. Outbound-only. |
| `supabase/migrations/` | Every schema change, in order. RLS is on from the first migration. |
| `scripts/` | One-shot ingestion: `ingest-exercises.ts` (free-exercise-db + Gym Visual media), `ingest-kot.ts` (Seth's KOT spreadsheets). |
| `programs/` | Normalized program data. `programs/kot/program.json` is the Knees Over Toes scaffold that Seth's spreadsheets reconcile against. |
| `data/raw/` | Downloaded corpora. Regenerated by the ingest scripts; not committed. |
| `data/reports/` | Output of the ingest scripts: `media-coverage.md` and `kot-reconciliation.md`. Read these after any ingest. |
| `docs/` | The contract (`PRD.md`, `RESEARCH_FOUNDATION.md`) and everything built on it. `docs/decisions/` holds the ADRs. |
| `.claude/` | Model routing, the three subagents, and plan-mode documents. Set up once, then left alone. |

## Quick start

```bash
git clone <this repo>
cd longevity-os
npm install
cp .env.example .env.local     # then fill it in — see docs/SETUP.md
npm run dev                    # http://localhost:3000
```

Useful scripts:

```bash
npm run check             # typecheck + engine tests. Run this before every commit.
npm run test              # engine unit + golden-file tests
npm run test:watch        # engine tests, watching
npm run ingest:exercises  # build the exercise library + media coverage report
npm run ingest:kot        # normalize docs/programs/kot/raw/ → programs/kot/*.json
npm run build             # engine, then web
```

The full first-run walkthrough — Supabase, Oura, Strava, Telegram, LM Studio, Gemini, Vercel — is [`docs/SETUP.md`](docs/SETUP.md). Budget about two hours for all of it, and it is fine to stop after the local dev server runs.

## The $0/month position

Every dependency is on a free tier, and the architecture is shaped by those tiers rather than fighting them.

| Piece | Tier | What it costs | The constraint it imposes |
| --- | --- | --- | --- |
| Vercel | Hobby | $0 | Non-commercial only. Cron is limited to roughly 2 jobs, once per day, with imprecise timing ⚠️ (RESEARCH §8) — so nightly sync lives here and nothing more frequent does. |
| Supabase | Free | $0 | 500 MB Postgres, 1 GB storage, pg_cron available. Projects pause after ~7 days of inactivity ⚠️ — daily use prevents it, and the mini's keep-alive ping is the insurance. |
| Oura API | Personal Access Token | $0 | PATs do not expire. Rate limit reported as 5,000 requests / 5 min — irrelevant at one user. |
| Strava API | Free developer app | $0 | 200 req / 15 min, 2,000 / day. The `/zones` endpoint needs a paid Strava subscription, so we never call it — we compute zones ourselves from the HR stream. |
| Telegram Bot API | Free | $0 | Webhook must be HTTPS. |
| LM Studio on the Mac mini | Local | $0 (electricity) | Must stay awake; outbound-only; no tunnels, no inbound ports. |
| Gemini | Free tier | $0 | Fallback only, when the mini has not claimed a job in 60 s. ⚠️ Free-tier RPM/RPD limits change — verify on the day you build. |
| Exercise data + media | Unlicense / permitted redistribution | $0 | Gym Visual media is 180×180 and requires attribution (see below). |

**Any paid dependency requires Seth's explicit yes.** There are no exceptions to this and no "it's only $5".

## Build status

Snapshot from the first build session, taken while several parts were still being written in parallel. **`npm run check` is the source of truth** — run it.

**What works**
- The contract and the evidence base: `docs/PRD.md`, `docs/RESEARCH_FOUNDATION.md`, `CLAUDE.md`. Stable, and read-only.
- **The exercise library is ingested.** `npm run ingest:exercises` merges 876 free-exercise-db rows with 1,324 Gym Visual rows into a **1,908-exercise library, 69.4% of it with an animated GIF**, 30.5% with static images, 3 records with no media at all. The full breakdown, including the 37 fuzzy joins that want a human eye, is in `data/reports/media-coverage.md`.
- **The engine has a pipeline, not just types.** `packages/engine/src/` holds readiness, ledger, exclusions, template, progression, deload, assembly, swaps, cardio, weekly dose and why-copy, with unit tests beside them and fixture days in `packages/engine/fixtures/`.
- **The schema exists.** `supabase/migrations/0001_init.sql` through `0005_cron.sql`: tables, RLS policies, the equipment catalog, the location presets, and the cron jobs.
- **The integrations are written**: Oura (client, schema, normalize), Strava (client, webhook, zones-from-HR-stream, normalize), Telegram (client, keyboards, router), and the LLM layer (provider, jobs, prompts, tools, fallback copy) over result-typed HTTP plumbing that never throws into the request path.
- **The KOT scaffold is normalized** to `programs/kot/program.json` — 26 steps — with a reconciliation report at `data/reports/kot-reconciliation.md` listing exactly where the public scaffold and Seth's sheet disagree.
- The web app renders a today card with the component set behind it: readiness ring, why line, sliders, minutes picker, location chip, clocks, rest timer, swap difficulty chips, sheets, toasts, skeletons.
- Documentation, ten ADRs, model routing and the three subagents — this pass.

**What is scaffolded**
- `apps/web/`: one route. The week carousel, session runtime, swap carousel, dashboard, settings, locations, programs and injuries screens are specified in `docs/DESIGN.md` and not yet built. No API route handlers yet — no Telegram webhook, no Strava webhook, no cron endpoints.
- `worker/`: the directory shape. The launchd job, the poll loop and the keep-alive remain.
- `packages/engine/`: golden-file tests on full session assembly, and the five named fixture days as a complete set (PRD §9).
- Auth, the PWA manifest and service worker, and the Vercel deploy.
- Nothing has been run against a real Supabase project, a real Oura token, or a real iPhone.

**What needs Seth** (full detail in [`docs/SETUP.md`](docs/SETUP.md))
1. Oura personal access token — **check for an existing one first** (PRD §12).
2. Strava developer app: client ID, client secret, redirect URI.
3. Telegram bot token from BotFather, plus his chat ID.
4. KOT spreadsheets → `docs/programs/kot/raw/`. The reconciliation report already names the gaps his sheet would close.
5. Old-app CSV exports → `docs/imports/raw/`.
6. Wyze scale screenshot and current weight.
7. LM Studio port confirmation and the installed model names (text + vision).
8. The chest strap, found and paired with the Strava app.
9. Vertical baseline: chalk, wall, 10 minutes.
